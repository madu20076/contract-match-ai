# Supabase Setup — Contract Match AI

Follow these steps to connect the app to a live Supabase database.

---

## 1. Create a Supabase project

1. Go to [supabase.com](https://supabase.com) and sign in (or create a free account).
2. Click **New project**.
3. Choose an organization, give the project a name (e.g. `contract-match-ai`), set a strong database password, and pick the region closest to your users.
4. Wait ~2 minutes for provisioning to finish.

---

## 2. Get your API credentials

1. In your project dashboard, go to **Settings → API**.
2. Copy two values:
   - **Project URL** — looks like `https://xxxxxxxxxxxx.supabase.co`
   - **anon / public key** — a long JWT starting with `eyJ…`

---

## 3. Create your `.env.local` file

In the project root, copy the example file and fill in your credentials:

```bash
cp .env.local.example .env.local
```

Edit `.env.local`:

```env
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...your-anon-key...
```

> **Never commit `.env.local` to git.** It is already listed in `.gitignore`.

---

## 4. Run the database schema

1. In your Supabase dashboard, go to **SQL Editor** (left sidebar).
2. Click **New query**.
3. Open `docs/supabase_schema.sql` from this project and paste the entire contents into the editor.
4. Click **Run** (or press `Cmd/Ctrl + Enter`).

This creates three tables:

| Table | Purpose |
|---|---|
| `business_profiles` | Submitted onboarding forms |
| `contracts` | Government contract opportunities |
| `contract_matches` | AI match scores linking profiles to contracts |

It also creates:
- GIN indexes on `naics_codes` and `certifications_required` for fast filtering
- Row-Level Security (RLS) policies (see [RLS section](#row-level-security) below)
- A `generate_matches_for_profile()` SQL function for server-side scoring
- Seed data for 6 sample contracts

---

## 5. Seed sample contracts (optional but recommended)

The schema SQL already includes an `INSERT` block at the bottom that loads 6 sample contracts. If you ran the full schema in step 4, the seed data is already in.

To verify, go to **Table Editor → contracts** in your Supabase dashboard. You should see 6 rows.

---

## 6. Restart the dev server

```bash
npm run dev
```

The app starts at **http://localhost:3002**.

Go to **http://localhost:3002/debug** to confirm Supabase is connected and the tables are populated.

---

## 7. Test the full flow

1. Visit `/onboarding`, fill out the form, and submit.
2. You'll see a success confirmation, then be redirected to `/dashboard`.
3. The dashboard will show matched contracts pulled from Supabase. If no matches exist yet, it falls back to demo data (see [Matching section](#generating-matches) below).

---

## Generating matches

After a business profile is created, matches must be generated by calling the `generate_matches_for_profile()` SQL function. In the current MVP, run it manually in the Supabase SQL Editor:

```sql
-- Replace <uuid> with the profile ID shown on the /debug page or in the business_profiles table
SELECT generate_matches_for_profile('<uuid>');
```

Future iterations can trigger this automatically via a Supabase Database Webhook or Edge Function after each `business_profiles` insert.

---

## Row-Level Security

The schema enables RLS on all three tables with these policies for the no-auth MVP:

| Table | Operation | Policy |
|---|---|---|
| `contracts` | SELECT | Public — anyone can read |
| `business_profiles` | INSERT | Public — anyone can submit a profile |
| `contract_matches` | SELECT | Public — any client can read matches |

Once you add Supabase Auth, tighten these policies to scope reads/writes to the authenticated user's own data.

---

## Environment variables reference

| Variable | Description |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Your project's REST API URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Public anon key for client-side queries |

Both variables are prefixed `NEXT_PUBLIC_` so the browser can access them. They are safe to expose to the client because RLS enforces data access rules on the database side.
